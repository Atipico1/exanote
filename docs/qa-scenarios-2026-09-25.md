# Exanote 사용자 관점 QA

기준 커밋: `c192ddf`. 시나리오 작성일: 2026-09-25.
실행 대상: `.build/DerivedData/Build/Products/Debug/Exanote.app`.
아래 항목은 테스트 계획이며 통과 결과가 아니다.

## 진행 방식

- 부모 에이전트가 기능 분석, 시나리오 작성, 문제 분류와 수정, HTML 보고서 통합을 맡는다.
- 개별 테스트와 수정 후 재현 확인은 사용자가 선택한 서브에이전트가 맡는다. 동시 실행은 항상 한 개뿐이다.
- 각 배치를 끝내고 증거를 저장한 다음 다음 배치를 시작한다. UI는 한 에이전트만 조작한다.
- 실행 중 앱의 경로와 빌드, 워커를 기록한다. 수정 후 빌드와 재실행을 확인하고 재테스트한다.
- 기존 회의와 폴더는 수정하거나 삭제하지 않는다. 생성 항목은 `QA-20260925-` 접두사를 사용한다.
- 테스트 오디오는 내용이 알려진 한국어·영어 합성 음성으로 준비한다. 실제 외부 회의나 타인 대화는 녹음하지 않는다.
- Drive 연동은 사용자가 승인한 범위에서 로그인 및 필요한 권한 승인을 진행한다. 기존 개인 기록의 의도하지 않은 전체 동기화를 피하고 QA 자료만 사용한다. 별도 사람에게 초대 메일은 보내지 않는다.
- 초기 상태와 변경한 설정을 기록하고 종료 시 복원한다. 모델 제거·재설치는 다른 작업에서 사용하는 모델인지 확인한 후 QA용 환경에서만 실행한다.
- 신규 사용자/빈 상태 및 파괴적 복구 실험은 별도 데이터 디렉터리를 사용한다. 운영 데이터로 crash/uninstall 테스트를 하지 않는다.

## 공통 판정과 증거

상태: `PASS`, `PARTIAL`, `FAIL`, `BLOCKED`, `NOT_RUN`. PARTIAL은 시나리오 일부만 실제 검증했음을 뜻한다. 코드만 확인한 경우 UI 통과로 판정하지 않는다.
모든 결과에 시나리오 ID, 실행 시간, 전제, 조작 단계, 기대/실제 결과, 화면 경로를 기록한다.
모든 버그는 수정 전 스크린샷을 저장한다. 동일 흐름의 수정 후 스크린샷과 재검증 결과를 연결한다.
스크린샷은 앱/브라우저 도구가 반환한 실제 픽셀만 사용한다. 재현이 안 되는 과거 상황은 재현 완료로 표기하지 않는다.
오류 문구, 무한 로딩, 화면 잘림, 데이터 유실, 검색 불일치, 접근성/키보드 문제를 모두 기록한다.
UI 증거를 API/파일 증거로 보강할 수 있지만 대체하지 않는다. 비밀값/토큰은 보고서에 포함하지 않는다.

## HTML 산출물

한 HTML 안에 전체 시나리오 판정표, 테스트 환경, 문제별 재현 단계·영향·원인·수정 파일·수정 전후 이미지, 미해결/차단 항목, 최종 회귀 결과를 담는다. 이미지는 data URI로 포함해 단독으로 열 수 있게 한다. 합성 데이터·실제 녹음·코드 검사·UI 검사 증거를 구분한다.
