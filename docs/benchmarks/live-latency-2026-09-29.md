# 실시간 영어 자막 지연 — 2026-09-29

Apple M4 · 메모리 32GB Mac에서 macOS `say`로 생성한 29.02초짜리 영어 회의(7개 발화)를 로컬 스트리밍 API에 실제 재생 속도로 입력했다. Qwen3-ASR MLX 모델과 번역 모델을 미리 연 뒤, 각 발화 시작부터 **첫 세 단어가 영어 미리보기 또는 확정 행에 나타난 시각**을 측정했다. 청크 요청은 48 kHz stereo float32로 보냈다. 실제 마이크 캡처, 네트워크 회의 앱, SwiftUI 화면 렌더링은 이 측정에 포함되지 않는다. 각 설정은 한 번씩 실행했다.

| 오디오 전송 및 ASR 디코딩 청크 | 발화별 영어 표시 지연 중앙값 | 관측된 최대 지연 | 음성 입력 종료 시 처리 밀림 |
| --- | ---: | ---: | ---: |
| 1.0초 (현재 앱 설정) | 1.58초 | 1.65초 | 0.20초 |
| 0.75초 (실험) | 1.60초 | 2.48초 | 0.28초 |
| 0.5초 (실험) | 1.34초 | 3.06초 | 2.62초 |

세 설정의 최종 영어 전사 문장은 이 음성에서 같았다. 0.5초 설정은 초반 표시가 빨랐지만 후반에 처리 작업이 누적되어 더 늦어졌다. 따라서 현재 앱 설정은 1.0초이며, 청크를 줄였다는 이유만으로 지연이 줄어든다고 볼 수 없다.

이 표는 **영어 전사 지연**이다. 한국어 번역 완료 시간은 재지 않았고, 한국어가 1초 안에 표시된다는 의미가 아니다. 앱은 같은 화자의 연속 발화를 모아 번역하므로, 한국어는 발화가 끝나고 추가 추론이 끝난 뒤 나타날 수 있다. 여기의 최대값도 일곱 발화에서 **관측된 최대값**일 뿐 서비스의 지연 상한이 아니다.

음성은 `scripts/generate_live_synthetic.py`의 `demo_thirty_seconds`로 만들었다. 위 지연 수치는 별도의 일시적 계측 스크립트로 기록했으며, 그 스크립트는 저장소에 포함하지 않았다. 따라서 이 수치를 그대로 재현하는 공개 명령은 아직 없다.
